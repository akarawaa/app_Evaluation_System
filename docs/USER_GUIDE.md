## 1. ผู้ดูแลระบบ (super_admin)

**คือใคร:** ผู้ดูแลแพลตฟอร์มระดับสูงสุด ไม่ได้สังกัดบริษัทลูกค้าใด ๆ — ปกติมีแค่ทีมงานของเราเอง

**เมนูที่เห็น:** แดชบอร์ด, งานที่รอฉัน, ใบประเมินผล, เปรียบเทียบผล, พนักงาน & สาขา (ของทุกบริษัทที่เข้าไปดู), **จัดการบริษัท** (เมนูนี้เห็นเฉพาะ super_admin)

**ทำอะไรได้บ้าง:**
| งาน | ทำได้ไหม |
|---|---|
| สร้างบริษัทใหม่ + สร้าง hr_admin คนแรกของบริษัทนั้น | ✅ (หน้า "จัดการบริษัท") |
| ระงับ/เปิดใช้งานบริษัท | ✅ |
| เชิญผู้ใช้ใหม่เข้าบริษัทใดก็ได้ | ✅ |
| ให้สิทธิ์บัญชีที่มีอยู่แล้วเข้าบริษัทที่สอง (multi-company) | ✅ — เฉพาะ super_admin ทำได้ (กันไม่ให้ hr_admin ให้สิทธิ์ตัวเองข้ามบริษัทได้เอง) |
| ดู/แก้ไขพนักงาน สาขา ใบประเมิน ของทุกบริษัท | ✅ ข้ามได้ทุก tenant |
| ให้คะแนน/อนุมัติใบประเมิน | ✅ ข้ามขั้นตอนได้ทุกขั้น (เทียบเท่า evaluator + dept_manager + md/gm + hr_admin ในคราวเดียว) — ใช้เฉพาะกรณีแก้ปัญหา ไม่ใช่ flow ปกติ |

## 2. ฝ่ายบุคคล (hr_admin)

**คือใคร:** ทีม HR ของบริษัทลูกค้าแต่ละราย — เป็นบทบาทที่มีสิทธิ์กว้างที่สุดในระดับบริษัทตัวเอง

**เมนูที่เห็น:** แดชบอร์ด, งานที่รอฉัน, ใบประเมินผล, เปรียบเทียบผล, **พนักงาน & สาขา**

**ทำอะไรได้บ้าง (เฉพาะในบริษัทตัวเอง):**
| งาน | ทำได้ไหม |
|---|---|
| เพิ่ม/แก้ไขพนักงาน (รายคน หรือ import CSV) | ✅ |
| เพิ่ม/แก้ไขสาขา | ✅ |
| เชิญผู้ใช้ใหม่เข้าระบบ (manager, dept_manager, md, gm, employee, hr_admin คนอื่น) | ✅ — เฉพาะเข้าบริษัทตัวเองเท่านั้น |
| ตั้งค่าสูตรคะแนนการเข้างาน (attendance formula) | ✅ |
| นำเข้าข้อมูลการเข้างาน (attendance import) | ✅ |
| บันทึกการรับทราบผลของพนักงาน (หลัง ผจก.แผนกอนุมัติ, ก่อน MD/GM อนุมัติ) | ✅ |
| อนุมัติขั้น MD/GM | ❌ — ไม่ใช่หน้าที่ hr_admin (ดูขั้นตอนอนุมัติด้านล่าง) |
| ปิดใบ/สรุปผล (finalize) | ✅ — เป็นคนเดียวที่ finalize ได้ |
| ลบพนักงาน/บริษัท | ❌ ไม่มีปุ่มลบถาวรในระบบ (ระงับบริษัทได้ แต่ super_admin เท่านั้น) |
| ให้สิทธิ์คนที่มีบัญชีอยู่แล้วเข้าบริษัทที่สอง | ❌ ต้องให้ super_admin ทำ |

## 3. หัวหน้างาน (manager) — ผู้ประเมินโดยตรง

**คือใคร:** ในระบบนี้ "manager" ไม่ใช่ role ที่ตายตัวกับคน แต่คือ **คนที่ถูกตั้งเป็น `supervisor_id` ของพนักงานคนนั้นในหน้าพนักงาน** — พูดง่าย ๆ คือหัวหน้างานตรงของพนักงานแต่ละคน

**เมนูที่เห็น:** แดชบอร์ด, งานที่รอฉัน, ใบประเมินผล, เปรียบเทียบผล (ไม่เห็นเมนู "พนักงาน & สาขา")

**ทำอะไรได้บ้าง:**
| งาน | ทำได้ไหม |
|---|---|
| สร้างใบประเมินให้ลูกทีมที่ตนเป็น supervisor | ✅ |
| กรอกคะแนน + ส่งใบประเมิน (submit) | ✅ เฉพาะใบของลูกทีมตัวเอง |
| บันทึกการรับทราบผลของพนักงาน (หลังพิมพ์กระดาษให้เซ็น) | ✅ เฉพาะใบของลูกทีมตัวเอง — ดู [ขั้นตอนการรับทราบ](#การรับทราบผลของพนักงาน-เป็นกระดาษเท่านั้น) |
| ดูใบประเมินของคนอื่นที่ไม่ใช่ลูกทีม | ❌ |
| อนุมัติใบของคนอื่น | ❌ |
| แก้ไขข้อมูลพนักงาน/สาขา | ❌ |

---

## 4. ผู้จัดการแผนก (dept_manager)

**คือใคร:** เช่นเดียวกับ manager — ผูกกับข้อมูลพนักงานผ่าน `manager_id` (หัวหน้าของ supervisor อีกที) ไม่ใช่ role คงที่

**เมนูที่เห็น:** แดชบอร์ด, งานที่รอฉัน, ใบประเมินผล, เปรียบเทียบผล

**ทำอะไรได้บ้าง:**
| งาน | ทำได้ไหม |
|---|---|
| อนุมัติใบประเมินขั้นที่ 1 (หลัง supervisor ส่ง) | ✅ เฉพาะใบของพนักงานในสายบังคับบัญชาตัวเอง |
| บันทึกการรับทราบผลของพนักงาน | ✅ เฉพาะใบของพนักงานในสายบังคับบัญชาตัวเอง |
| ตีกลับใบประเมินให้แก้ (return to draft) | ✅ ในขั้นตอนที่ตัวเองรับผิดชอบ |
| กรอกคะแนนแทน supervisor | ❌ (เว้นแต่ตัวเองเป็น supervisor ของคนนั้นด้วย) |

## 5. กรรมการผู้จัดการ / ผู้จัดการทั่วไป (md / gm)

**คือใคร:** role คงที่ (ไม่ผูกกับข้อมูลพนักงานเหมือน manager/dept_manager) — เป็นผู้อนุมัติขั้นสุดท้ายก่อนส่งให้ HR ปิดใบ **md และ gm ใช้แทนกันได้** (คนละชื่อตำแหน่ง แต่สิทธิ์เหมือนกันทุกประการ)

**เมนูที่เห็น:** แดชบอร์ด, งานที่รอฉัน, ใบประเมินผล, เปรียบเทียบผล

**ทำอะไรได้บ้าง:**
| งาน | ทำได้ไหม |
|---|---|
| อนุมัติใบประเมินขั้นสุดท้าย (หลัง dept_manager อนุมัติ) | ✅ ทุกใบในบริษัทตัวเอง ไม่จำกัดเฉพาะสายบังคับบัญชา — แต่ **อนุมัติไม่ได้จนกว่าจะมีการบันทึกรับทราบผลของพนักงานแล้ว** |
| บันทึกการรับทราบผลของพนักงาน | ❌ ตั้งใจแยกมือกัน — คนบันทึกรับทราบต้องไม่ใช่คนอนุมัติขั้นถัดไป |
| ตีกลับใบประเมิน | ✅ ในขั้นตอนของตัวเอง |
| ปิดใบ/สรุปผล (finalize) | ❌ เป็นหน้าที่ hr_admin |

## 6. พนักงาน (employee)

**คือใคร:** บัญชี login สำหรับพนักงานทั่วไปที่ไม่มีหน้าที่ประเมินใคร — ใช้ดูผลของตัวเองและลงนามรับทราบ

**เมนูที่เห็น:** แดชบอร์ด, งานที่รอฉัน, ใบประเมินผล (เห็นเฉพาะใบของตัวเอง)

**ทำอะไรได้บ้าง:**
| งาน | ทำได้ไหม |
|---|---|
| ดูใบประเมินของตัวเอง (ทุกสถานะ) | ✅ |
| ดาวน์โหลด PDF ใบประเมินของตัวเอง | ✅ |
| ลงนามรับทราบผลด้วยตัวเองในระบบ | ❌ — **ยังไม่มีในระบบตอนนี้** การรับทราบผลปัจจุบันเป็นแบบกระดาษเท่านั้น (พิมพ์ให้เซ็นตัวเป็น ๆ แล้วให้หัวหน้างาน/ผจก.แผนก/HR บันทึกผลแทน — ดูหัวข้อถัดไป) ระบบรับทราบแบบอิเล็กทรอนิกส์ในตัวเป็นแผนเฟสถัดไป ยังไม่ได้สร้าง |
| ดู/แก้ไขข้อมูลพนักงานคนอื่น | ❌ |
| ให้คะแนน/อนุมัติ | ❌ |

> หมายเหตุ: บัญชี `employee` ไม่จำเป็นเสมอไป — ทุกอย่างที่เกี่ยวกับการรับทราบผลทำผ่านหัวหน้างาน/ผจก.แผนก/HR อยู่แล้ว (ดูด้านล่าง) พนักงานที่ยังไม่มี login ก็ผ่าน flow ได้ครบเหมือนกัน บริษัทส่วนใหญ่จึงไม่จำเป็นต้องสร้างบัญชีให้พนักงานทุกคน — สร้างเฉพาะคนที่ต้องการเข้ามาดูผลตัวเองผ่านเว็บก็พอ

### การรับทราบผลของพนักงาน (เป็นกระดาษเท่านั้น)

ระหว่างขั้น "ผจก.แผนกอนุมัติ" กับ "MD อนุมัติ" ต้องพิมพ์ใบประเมินให้พนักงานเซ็นรับทราบตัวเป็น ๆ ก่อนเสมอ — **MD/GM จะอนุมัติขั้นสุดท้ายไม่ได้จนกว่าจะมีการบันทึกรับทราบนี้แล้ว** (ระบบบังคับไว้)

คนที่บันทึกผลการรับทราบแทนพนักงานได้ (เลือกได้ 1 ใน 3): **หัวหน้างานผู้ประเมิน (supervisor), ผจก.แผนก (manager), หรือ hr_admin** — ตั้งใจไม่ให้ md/gm บันทึกเอง เพราะเป็นคนอนุมัติขั้นถัดไปทันที ต้องแยกคนละมือกัน

ผลการรับทราบมี 3 แบบ: รับทราบ / รับทราบแต่มีความเห็นแย้ง / ปฏิเสธการลงนาม — พร้อมช่องความเห็นและแนบไฟล์สแกนได้

## ขั้นตอนการอนุมัติใบประเมิน

ใบประเมิน 1 ใบ ไหลผ่านสถานะตามลำดับนี้ อ้างอิงจาก **สายบังคับบัญชาจริงของพนักงานคนนั้น** (ตั้งค่าไว้ในหน้า "พนักงาน & สาขา" — ไม่ใช่ role เฉย ๆ):

```
ร่าง (draft)
  ↓  supervisor กรอกคะแนน + ส่ง (submit)
ส่งแล้ว (submitted)
  ↓  dept_manager (= manager_id ของพนักงาน) อนุมัติ
ผจก.แผนกอนุมัติ (dept_approved)
  ↓  supervisor / ผจก.แผนก / hr_admin บันทึกการรับทราบผลของพนักงาน (บังคับ ก่อนขั้นถัดไปเสมอ)
  ↓  md / gm อนุมัติ
MD อนุมัติ (md_approved)
  ↓  hr_admin ปิดใบ (finalize)
ปิดใบแล้ว (finalized)
```

ทุกขั้นตอน **"ตีกลับ" (return)** ได้ — ใบจะกลับไปเป็นร่างให้แก้ไขใหม่ โดยผู้มีสิทธิ์อนุมัติขั้นนั้น ๆ เท่านั้นที่ตีกลับได้

`super_admin` ข้ามทำแทนได้ทุกขั้นตอนไม่มีข้อยกเว้น (ใช้กรณีแก้ปัญหาเท่านั้น ไม่ใช่ flow ปกติที่ควรใช้ประจำ) ส่วน `hr_admin` ทำแทนได้เฉพาะ **บันทึกรับทราบผล + ปิดใบ** เท่านั้น — กรอกคะแนน/ส่ง ต้องเป็น supervisor ที่ถูกตั้งไว้จริงเท่านั้น (แม้เป็น hr_admin ก็ทำแทนไม่ได้ถ้าไม่ใช่ evaluator ของใบนั้น) และ **อนุมัติขั้น ผจก.แผนก/MD/GM ก็แทนไม่ได้เช่นกัน**

## เข้าสู่ระบบ / ลืมรหัสผ่าน

1. เข้าเว็บที่ URL ของระบบ (Vercel) → กรอกอีเมล + รหัสผ่าน
2. ถ้าลืมรหัสผ่าน กดลิงก์ **"ลืมรหัสผ่าน?"** หน้า login → กรอกอีเมล → ระบบส่งลิงก์ตั้งรหัสผ่านใหม่ไปทางอีเมล (ลิงก์หมดอายุใน 30 นาที)
3. ตั้งรหัสผ่านใหม่เองได้ทันที ไม่ต้องรอ HR/admin ตั้งให้

## การสลับบริษัท (สำหรับคนที่ดูแลหลายบริษัท)

ถ้า 1 อีเมลถูกให้สิทธิ์เข้ามากกว่า 1 บริษัท (เช่น ที่ปรึกษา HR ที่ดูแลหลายบริษัท) — หลัง login จะเห็น**ตัวเลือกสลับบริษัท**อยู่ข้าง ๆ ชื่อผู้ใช้บนแถบเมนูด้านบนโดยอัตโนมัติ (ถ้ามีบริษัทเดียว จะไม่เห็นตัวเลือกนี้ ไม่ต้องกังวลว่าหายไปไหน)

การสลับบริษัทจะเปลี่ยน "บริษัทที่ active อยู่" ของ session — ข้อมูลพนักงาน/ใบประเมินที่เห็นหลังสลับจะเป็นของบริษัทใหม่ทั้งหมด บทบาท (role) ก็จะเปลี่ยนตามสิทธิ์ที่มีในบริษัทนั้น ๆ (เช่น เป็น hr_admin ในบริษัท A แต่เป็นแค่ manager ในบริษัท B)

**การให้สิทธิ์เข้าบริษัทที่สอง** ทำได้โดย super_admin เท่านั้น ผ่านหน้ารายละเอียดบริษัท → แบบฟอร์ม "ให้สิทธิ์ผู้ใช้เดิมเข้าบริษัทนี้" (กรอกอีเมลที่มีบัญชีอยู่แล้ว + เลือกบทบาทในบริษัทนี้)

## บัญชีสำหรับทดลองใช้งาน (Pilot)

> **หมายเหตุด้านความปลอดภัย:** ระบบไม่เก็บรหัสผ่านของผู้ใช้เป็นตัวหนังสือที่ไหนเลย (Supabase Auth
> เข้ารหัสไว้ฝั่งเดียว) — รหัสผ่านเริ่มต้นของแต่ละคนคือค่าที่ **ผู้เชิญ (คุณ) เป็นคนพิมพ์เองตอนกดเชิญ**
> เอกสารนี้จึงไม่สามารถ "สรุป" รหัสผ่านจริงให้ล่วงหน้าได้ — ใช้ตารางด้านล่างเป็นแบบฟอร์มบันทึกเอง
> ระหว่างสร้างบัญชีทดลอง แล้วเก็บไฟล์นี้ไว้ในที่ปลอดภัย (ไม่ commit เข้า git, ไม่ส่งผ่านแชทสาธารณะ)

**ขั้นตอนแนะนำสำหรับสร้างบัญชีทดลอง:**
1. Login ด้วย super_admin หรือ hr_admin ของบริษัท → ไปหน้า "พนักงาน & สาขา" (hr_admin) หรือ "จัดการบริษัท" → เลือกบริษัท (super_admin)
2. กรอกฟอร์ม "เชิญผู้ใช้เข้าระบบ" — อีเมลจริงของผู้ทดลองใช้ + **รหัสผ่านชั่วคราว** (≥ 8 ตัวอักษร) + เลือกบทบาท
3. แจ้งอีเมล + รหัสผ่านชั่วคราวให้ผู้ทดลองใช้ **ทางช่องทางที่ปลอดภัย** (ไม่ใช่อีเมล/แชทที่คนอื่นเห็นได้) แล้วให้เขา **เปลี่ยนรหัสผ่านทันทีหลัง login ครั้งแรก** ผ่านหน้า "ลืมรหัสผ่าน" หรือฟีเจอร์เปลี่ยนรหัสผ่านในระบบ — อย่าใช้รหัสผ่านชั่วคราวต่อเนื่องระยะยาว
